DBMS Weekly — 2026-11-02 (week of Nov 2–8)

Days before 19 RC2, Andrew Dunstan reverted the to_json/to_jsonb immutability change after it let JSON expression indexes go stale; anything built on 19rc1 that depends on it must be redefined before dump/restore or pg_upgrade. The 18.7/17.12/16.16/15.20/14.25 notes collect two checkpoint-race fixes, Memoize and Sort wrong results, a pg_trgm GiST fix that needs a REINDEX, and a walsender lost wakeup. AI-found bugs became the list's meta-story, from a tester holding over 1,000 to Peter Geoghegan's LLM-written rival to the nbtree prefix-compression patch. On the blogs failover dominated, alongside UUIDv4's real insert cost, a TOAST page-size trap and PostHog leaving DuckDB.

PostgreSQL

  • UUIDv4 vs UUIDv7: what a random primary key costs in Postgres — on 18.6, once the primary key outgrew shared_buffers (~26 M rows), UUIDv4 inserts ran at 0.62–0.69× an ordered key and wrote 1.5–1.9× the WAL per row; generate v7 server-side. (Nikolay Samokhvalov · postgres.ai)
  • Postgres logical replication beyond one writer — four regions of pg_auto_failover groups linked only by core logical replication: a planned failover lost nothing, kill -9 gave 2–4 duplicates and no holes, emptied synchronized_standby_slots lost 3–13 rows; DDL remains the gap. (Dimitri Fontaine · tapoueh.org) [by pg_auto_failover / pgcopydb author]
  • Fencing a Postgres primary that might still be alive — promotion alone doesn't stop an old primary that a session can switch to synchronous_commit = local, so Ubicloud cuts its network (host veth, force-detached AWS NIC, deleted GCP NIC) and promotes anyway if every fence fails. (Furkan Sahin · clickhouse.com / Ubicloud) [vendor blog — substantive]
  • Designing a reliable unplanned failover — the opposite answer: no lease; Neki fails over only when a reachable replica reports broken replication and none contradicts it, with keepalives and wal_receiver_timeout tuned so crashes, drops and freezes look alike. (Shlomi Noach · planetscale.com) [vendor blog — substantive]
  • PostgreSQL document compression: TOAST thresholds, storage policies, and page size — TOAST tries compression only past a hardcoded quarter-page gate that toast_tuple_target can't lower, so on 16/32 KB builds of 19rc1 3.9 KB and 7.7 KB JSONB documents stop compressing. (Franck Pachot · dev.to)
  • Patroni, Ubuntu 24.04, and two unplanned PostgreSQL failovers — unattended-upgrades updated zlib, needrestart restarted the custom Patroni unit, and with KillMode=control-group the stop signal reached Postgres too: two failovers in a day, traced through journal and dpkg logs. (Franck Pachot · dev.to)
  • systemd-sysusers and directory-managed Postgres accounts — PGDG RPMs now create postgres via sysusers.d at early boot, before AD/LDAP answers, so a directory-managed account gets a local twin with another UID and the cluster fails to start after reboot. (Nick Ivanov · enterprisedb.com)
  • Establishing the PostgreSQL standard: PGConf.dev 2026 part two — postgres-compat, a reference test for "Postgres-compatible": Postgres's own 200 regression tests and 117 isolation specs run unchanged against the target, plus 74 probes for silent failures and contrib behaviour. (Jimmy Angelakos · vyruss.org)
  • Building a table access method, part 7: storing and reading rows — pg_memtable gains INSERT and a full scan over its DSM arena: how slots carry rows into the AM, what a TID must encode, arena allocation, and visibility with two concurrent writers. (Mats Kindahl · dbmsdrops.kindahl.net)
  • "server closed the connection unexpectedly" in PostgreSQL — five causes behind libpq's message, each reproduced on 13–18 across six drivers and PgBouncer; no library surfaced the 57P02 crash notice, and an OOM kill logs exactly like kill -9. (Chris van Eijk · now-next.nl)
  • A month with WalShadow on ClickHouse Managed Postgres — decoding physical WAL outside Postgres, with no slot, held a 0.37–0.41 s median commit-to-visible latency up to 200,000 rows/s, while logical-replication ClickPipes tracked its 60 s sync interval. (Hidehiko Asahi · clickhouse.com) [vendor blog] [unverified: private preview]
  • Why I'm maintaining a VectorChord fork and pg_mooncake — VectorChord, silent since April, lives on as pgsty/* forks for PG 14–18; a pg_mooncake port to pg_duckdb 1.2 went upstream once Mooncake Labs said it would keep maintaining it. (Ruohang Feng · vonng.com)
  • OrioleDB v1.10.1 and v1.10.2 — releases drop betaN numbering a week after the public beta, with no storage or WAL format change. Fixes cover lost updates under REPEATABLE READ, wrong rows through bridged (GIN etc.) indexes, checkpointer and undo-chain PANICs, and decoding crashes on TOASTed tables. Transaction streaming is now disabled at decoding startup cluster-wide. (orioledb · GitHub) [release]
  • pg_duckdb 1.2.0 — moves to DuckDB 2.0.0 and is explicitly marked experimental, "not ready for production use", over unresolved user reports. Adds initial PostgreSQL 19 support, INSERT INTO <pg table> SELECT … through DuckDB, and installation into a non-public schema. (duckdb · GitHub) [release]
  • psqlODBC 18.00.0006 — a security release that "fixes multiple security issues"; the announcement points only to the changelog. (pgsql-announce) [release] [unverified: individual issues not read]
  • AgensGraph 2.18 — rebased on PostgreSQL 18.6, it adds the first ISO GQL clauses (LET, FOR, FILTER, NEXT, FINISH) and graph subqueries. Variable-length traversals now use the edge label's index at each hop; a two-hop query that timed out at 20 s takes milliseconds. (pgsql-announce) [release] [unverified: self-reported]
  • pgBadger 13.3 — no longer counts a query twice when both log_min_duration_statement and auto_explain log it. Also parses auto_explain's query parameters, fixes multiline statements and --dbuser filtering, and uses per-run temp files so concurrent runs don't collide. (pgsql-announce) [release]
  • HypoPG 1.4.5 — fixes relid handling in hypothetical indexes that could crash the backend, and a long-standing thinko in hypo_estimate_index. (pgsql-announce) [release]
  • Brume 2.1 — an Apache-2.0 tool that copies a subset of a database for testing with personal data pseudonymised. Format-preserving encryption rewrites primary keys and the foreign keys pointing at them, so referential integrity holds without disabling triggers. (pgsql-announce) [release]

Research & cutting edge

  • Correctness firewalls for synthesized database components — agent-written engine parts go behind boundaries that may change speed but never results: advisory for cardinality, guarded for search, certified for compression; synthesized search beat learned indexes up to 3×. (Amiri, Binnig, Kipf, Kraska, Marcus et al.) [paper]
  • GenDB-V: AI-generated and formally verified database engines — per-query code ships with proofs against a fixed SQL semantics and runs 22–61× faster than DuckDB and Umbra, while a test-only LLM baseline was wrong on 16 of 28 templates. (Lao, Trummer) [paper] [unverified: template-specialised speedups]
  • When is one query per template enough? Moving a learned cost model to new hardware — on PostgreSQL in six environments, serial and parallel lines plus one measured query per template reach median Q-error 1.10 (TPC-H) and 1.19 (TPC-DS), near full retraining. (Patel) [paper]
  • Fidelity synopses: choosing an ANN index configuration per query — landmark cells record which index configuration met the recall target on sample queries, so the optimizer picks the cheapest one per query in 21–32 µs; median cost 0.72× of static. (Ramanatha, Singh, Ramanath) [paper]
  • PQR-Search: per-query recall guarantees for ANN in dynamic vector databases — indexes tuned to 0.99 average recall left 5–19% of queries below it; a random rotation inside IVF gives per-query guarantees that survive updates, at 2.5× HNSW latency. (Loh, Lee) [paper]
  • Eliminating servers in state machine replication — both the total order and the materialised state live on disaggregated storage, with clients sharing one state copy through the log; the AirDB KV store cold-starts 10–45× faster than etcd. (Park, Hu, Yu, Balakrishnan, Park) [paper]
  • Quirinus: when deterministic concurrency control beats 2PL and OCC for geo-replication — an analytical model of when ordering a batch before execution pays off, then a DCC system reaching up to 6.2× Tiga's TPC-C throughput. (Mao, Zhang, Zhang, Jacobsen) [paper] [unverified: single configuration]
  • Recast: storage-resident ANN that handles deletes — raw vectors stay on disk and an uncertainty-bounded quantised IVF stays in memory, fetching only candidates that need refinement; batched updates run 3.1–37× faster than SPFresh and OdinANN. (Yang, Tao, Dong, Chen) [paper]
  • USDB: ByteDance's sequence storage for recommender systems — an LSM with time-staged compaction that materialises per-application histories; production migration cut mean write latency 85.8% and infrastructure cost 42.1%. (Zhu, Cai, Yu, … Chai) [paper] [unverified: production self-report]
  • Withdrawn: "Teach Your DBMS to LIKE Strings" — the TUM Aho-Corasick wildcard-join paper (up to 30.6× over DuckDB) was withdrawn on Nov 2: "The invariant in this manuscript is wrong." (Nguyen, Ginter, Nguyen, Neumann, Leis) [paper]

International (non-English sources)

(alex7six · Tantor on Habr) [ru] [vendor blog — substantive] (orig: Регистр бухгалтерии, итоги и боль закрытия месяца: разбор кейса оптимизации)

(岳麓丹枫 · modb.pro) [zh] (orig: pg_walex —— WAL 解析为 SQL / undo SQL 工具使用经验)
  • postgres_fdw from 27 minutes to 1 second — ANALYZE on foreign tables took a join from 1,622 s to 2.2 s and fetch_size 10,000 to 1.0 s; enum filters aren't shipped, so use = ANY(array(subquery)). (伊藤 寿浩 · FORCIA on Zenn) [ja] (orig: データ連携をボトルネックにさせないためのpostgres_fdwチューニング)

(DanielSpravtsev · Habr) [ru] (orig: Один запрос: 4 мс с литералами и 3 секунды из Laravel. Как плейсхолдеры в IN выключают loose index scan в MySQL)
  • Why fallback replication from GreatSQL 8.0 to MySQL 5.7 stopped on collation #255 — a routine's binlog events carry its definition-time character_set_client, so recreate routines under a collation 5.7 knows. (GreatSQL community · modb.pro) [zh] (orig: GreatSQL 8.0回流MySQL 5.7主从复制中断分析排查过程)

(杨泽 / 勉仁 · Alibaba 数据库内核月报) [zh] (orig: 从 Volcano 到 Morsel：DuckDB 并行执行器的设计原理 / 树怎么变成一组流水线：DuckDB 的 Pipeline 切分)
  • Inside Oracle 7.2–9.2 WRAP — pre-10g wrapping stores the PL/SQL front end's DIANA tree with names in a plain lexicon, so V1 wrapped units can be reversed; the format was mapped from 332 reference units. (softwind · Habr) [ru] (orig: Wrap PL/SQL в Oracle 7.2–9.2: DIANA, слои преобразования и формат V1)
  • Snowflake's classic clustering looked at only the first 5 bytes of a key — that is 1.3 Japanese characters, so 東京都… prefix filters pruned to every Tokyo partition; Optima Clustering's 1 KB keys prune to one. (indigo13love · Snowflake Japan on Zenn) [ja] (orig: Snowflake: Optima Clustering による 1KB クラスタリングキーでの日本語フィルタの改善)
