## PostgreSQL

- **[Concurrent sequence-refresh race fixed — take two](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47439.html)** — resolves last week's cliffhanger: after the "reject concurrent refreshes" approach was reverted for buildfarm flakiness, this fix instead stops any running sequencesync worker before `ALTER SUBSCRIPTION … REFRESH SEQUENCES` resets sequences to INIT, closing a silent-lost-refresh race (worker's stale publisher value could overwrite the reset). Race-free because AlterSubscription already holds AccessExclusiveLock. Reported by Noah Misch; backpatched to 19. *(Amit Kapila · pgsql-committers)* `[committed]`
- **[Another empty-nbtree SSI race closed](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47512.html)** — the earlier fix (f9b7fc65) only covered `_bt_search`; scans without useful insertion scankeys return early via `_bt_endpoint`, which still didn't recheck an empty index, so a serializable reader could miss concurrently inserted tuples while the writer never saw its predicate lock. Backpatched to 14, alongside a week of new nbtree test coverage (backwards scans, empty-index predicate locking, `_bt_set_startikey` row compares). *(Peter Geoghegan · pgsql-committers)* `[committed]`
- **[Guard against a stuck WAL summarizer](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47484.html)** — the summarizer was passed the latest end-of-WAL even when reading a historic timeline; with a corrupted or hand-renamed `.partial` file in the archive it could keep retrying an invalid record and wedge, breaking incremental backup. Backpatched to 17. Reported by Fabrice Chapuis, analyzed by Thom Brown (credited "using claude"). *(Robert Haas · pgsql-committers)* `[committed]`
- **[JSON_ARRAY(subquery) dropped its FORMAT clause on deparse](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47527.html)** — more than cosmetic: a view storing `JSON_ARRAY(subquery FORMAT JSON)` would deparse without the FORMAT, and `FORMAT JSON` changes the result (a text value treated as already-formatted JSON vs. a quoted string). Fixed by recording the input FORMAT for ruleutils; catversion bump, backpatched to 19. *(Chao Li, committed by Richard Guo · pgsql-committers)* `[committed]`
- **[Logical replication hardening](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47497.html)** — a cluster of subscriber-side fixes landed: subscription conninfo is now re-validated on owner change; apply workers ignore `default_transaction_*` GUCs that could otherwise derail them ([msg47464](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47464.html)); and sequence synchronization now [rejects pre-PostgreSQL-19 publishers](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47488.html) rather than misbehaving. *(Fujii Masao, Amit Kapila · pgsql-committers)* `[committed]`
- **[REPACK keeps getting polished in beta](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47444.html)** — PG19's new in-core online-rewrite command drew more cleanup this week (partitioned-table repack code refactor, an LSN-format fix in the REPACK worker's debug output), a reminder that CONCURRENTLY mode is still settling before GA. *(Álvaro Herrera · pgsql-committers)* `[committed]`
- **[pg_dump: restore of partitions with exclusion constraints](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47450.html)** — fix for restoring partitions carrying exclusion constraints. *(Álvaro Herrera · pgsql-committers)* `[committed]`
- **Master grab-bag** — [psql `\l+` now shows database size to `pg_read_all_stats`](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47505.html) *(Fujii Masao)*; a [planner micro-opt skips `get_relids_in_jointree()` when there are no PlaceHolderVars](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47434.html) *(Richard Guo)*; [pg_control_checkpoint() exposes logical-decoding status](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47462.html) *(Masahiko Sawada)*; a run of pgstats [out-of-memory hardening](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47483.html) *(Michael Paquier)*; and a doc note that [granting TRIGGER or REFERENCES is a privilege-escalation risk](https://mail-archive.com/pgsql-committers@lists.postgresql.org/msg47454.html) *(Robert Haas)*. `[committed]`

### Reading — REPACK & MVCC

- **[Every UPDATE Leaves a Ghost: MVCC, Bloat, and VACUUM in PostgreSQL](https://planetscale.com/blog/postgresql-mvcc)** — MVCC/dead-tuple/bloat walkthrough with runnable psql examples; the "why you eventually need to rewrite a table" backstory to REPACK. *(Jan Nidzwetzki, Etienne Berube, Ahmed Darwich · planetscale.com)* `[vendor blog — substantive]`
- **[What's new in Postgres 19](https://planetscale.com/blog/whats-new-in-postgres-19)** — feature roundup centered on `REPACK (CONCURRENTLY)`, the in-core online rewrite that folds VACUUM FULL and CLUSTER into one command with a non-blocking mode. *(Ahmed Darwich · planetscale.com)* `[vendor blog]`

## Wider DBMS & distributed data

- **[PostgresBench: the performance cost of High Availability on managed Postgres](https://clickhouse.com/blog/postgresbench-ha)** — a benchmark isolating how enabling HA (synchronous replication) changes throughput/latency across managed Postgres offerings; useful framing even read skeptically as a vendor benchmark. *(Lionel Palacin, Sai Srirampur, Andrey Chudnovskiy · clickhouse.com)* `[vendor blog]`

## Research & cutting edge

- **[RCC: Speculative Write Versioning with Redo Logs](https://arxiv.org/abs/2607.19697)** — a write-versioning scheme that speculatively applies redo logs; storage/logging-layer work from a group with a strong flash-DB track record. *(Yoo, Moon, Sang-Won Lee, Park)* _[paper]_
- **[Semantic Conformance of Concurrency-Control Protocols under Mixed Isolation Levels](https://arxiv.org/abs/2607.16696)** — checks whether CC protocols actually honor their claimed semantics when transactions run at *different* isolation levels simultaneously — exactly the messy real-world case. *(Xiong, Wei, Liu, Chen, Ge · SCCP 2026)* _[paper]_
- **[Extending Elle for Transaction Workloads with Duplicate Values](https://arxiv.org/abs/2607.17515)** — extends Elle, the black-box transactional-anomaly checker, to cope with workloads where values repeat (a known blind spot when inferring the version order). *(Cai, Liu, Wei · SCCP 2026)* _[paper]_
