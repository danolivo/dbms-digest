# DBMS Weekly — 2026-11-09 (week of Nov 9–15)

_The Nov 12 update releases fixed 52 CVEs and over 140 bugs, closed out PostgreSQL 14, and shipped 19 RC 2 ahead of a Nov 19 GA. The CVE-2026-6460 fix versions composite datums, which breaks the extension ABI, so packagers now pin extensions to the new server libs. The list kept landing wrong-result fixes in Memoize, initplans, FULL JOIN and GROUP BY removal, while an auto_explain crash will ship in 19.0 behind the release freeze. On the blogs: pg_orca's PostgreSQL-aligned cost model, a glibc collation corruption catalogue, and three migration reports from Heroku, pgvector and Azure._

## Research & cutting edge

- **[Choosing PostgreSQL's join-order solver per query](https://arxiv.org/abs/2611.15263)** — Two features computed from random join orders route each query among DP, GEQO and MCTS; on IMDb-CEB this nearly doubles the gain of routing by relation count alone. *(Burlakov, Rybakina, Kudashev et al.)* _[paper]_
- **[DBLog incremental snapshots that also delete orphan rows](https://arxiv.org/abs/2611.10810)** — The chunked-snapshot algorithm behind Debezium and Flink CDC now emits deletes for keys a chunk's range select didn't return, repairing drifted sinks; safety proven in Isabelle/HOL and Lean 4. *(Andreas Andreakis)* _[paper]_
- **[PaB-tree: a batch-parallel B+-tree with sequential I/O bounds](https://arxiv.org/abs/2611.09172)** — Overflow and underflow repairs touch only the parent, never siblings, keeping B+-tree cache bounds with polylog span; up to 3.6× faster batch insertion than Bw-tree/Masstree-class baselines. *(Men, Gu, Sun, Xu)* _[paper]_
- **[Does an LLM Oracle-to-PostgreSQL migration agent actually learn?](https://arxiv.org/abs/2611.16143)** — An audit found 72% of held-out units shared a PostgreSQL reference with training, and 10–22% of PL/SQL units PostgreSQL accepted behaved differently from Oracle. *(Grynets, Lyashkevych et al.)* _[paper]_
- **[Raven: a lakehouse catalog with multi-table snapshot isolation](https://arxiv.org/abs/2611.15975)** — Transactional metadata lives in a database while file metadata stays in Iceberg or Delta, adding merge-on-read commits and safe global GC at a fraction of DuckLake's catalog footprint. *(Oh, Mehra, Kimball, Deshpande)* _[paper]_
